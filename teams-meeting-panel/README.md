# Teams meeting panel

Separate Teams tab entry points for the existing authorized live transcript and
analysis streams. It is outside the root frontend workspace and does not change
the current shell, desktop bundle, gateway or shared speech settings.

## Delivered behavior

- TeamsJS configuration selects an existing canonical meeting by title. The API
  checks the viewer's platform JWT and meeting access before saving or reading.
- Keycloak authorization-code/PKCE login runs in a Teams authentication popup.
  Teams context, organizer names and chat IDs are never authentication evidence.
- Access and refresh tokens stay in memory, not URLs or application storage.
  API requests are same-origin bearer requests, omit cookies, and reject redirects.
- The panel shows new live transcript, summary, decision and action events without
  waiting for recording to stop. It does not relabel a saved result as live.
- Source IDs and canonical web transcript folding are preserved. No punctuation,
  owner name or date is guessed or repaired in the client.
- On access denial, unavailable meeting, or failed periodic access check, visible
  meeting content is cleared and both live streams are closed. Authorization is
  rechecked every 60 seconds with a 15-second token/header deadline. Network errors
  on a stream retry after five seconds. The server has no replay; gaps are shown.
- An optional, default-off Outlook picker lists only server-authorized organizer
  events for the selected canonical meeting. Browsing/selecting a radio button
  does not schedule a join: the user explicitly confirms the event. Only its
  opaque event ID is submitted, never an organizer, join URL or browser timing.
- The picker reads status before offering selection, periodically rechecks it,
  and can cancel pending selections. Dispatching/joined calls are not presented
  as cancellable pending selections. A lost mutation response locks further
  mutations until status is read; no mutation is automatically retried.
- Calendar-only permission denial clears calendar choices without logging a
  read-only live viewer out. A 401 ends the panel session. Responses and token/
  network/body waits are bounded. Truncated lists invite narrowing the date range.
- If a future meeting's live view is unavailable, the user can reopen it with a
  fresh server access check once the meeting starts. Bot joined status does not
  by itself claim that live audio or analysis is working.

## Build and check

Use Node 24 or later in this directory:

```sh
npm ci --workspaces=false --ignore-scripts --no-fund
npm test
npm run build
```

The dedicated workflow produces a static `dist` artifact with `SOURCE_COMMIT`.
It does not deploy or replace the existing frontend image.

## TEST installation contract

1. Publish the static artifact under the approved origin's `/teams/panel/` path
   with correct JavaScript/CSS MIME types. Missing assets must return 404, not
   shell HTML. Keep the platform `/api/` routes on that same origin.
2. Serve `/teams/panel/config.json` using `config.example.json` as a shape only.
   Supply the approved Keycloak URL, realm and **public** client ID. No client
   secret, worker control key or Microsoft application credential belongs here.
   Keep `calendarEnabled` false until backend #1195, dispatch-time recording
   permission revalidation, approved Graph permissions and real tenant acceptance
   are complete. Setting this flag does not configure or authorize the backend.
3. The approved Keycloak client needs Standard Flow, PKCE S256, exact valid
   redirect `https://testai.acik.com/teams/panel/login.html`, and web origin
   `https://testai.acik.com` for code redemption/refresh. Do not add wildcard
   redirects. Reuse approved platform role/audience mappings; Teams membership
   alone does not grant meeting access.
4. Configure the panel path's CSP for the approved Teams/Microsoft 365 frame
   ancestors and Keycloak connect origin. Do not apply `X-Frame-Options: DENY`
   or `SAMEORIGIN` to the embedded panel path. Authentication popup responses must
   not use `Cross-Origin-Opener-Policy: same-origin`, which breaks Teams popup
   communication. Keep these settings scoped to the panel, not the existing app.
   Use `Cache-Control: no-store` and `Referrer-Policy: no-referrer` on login/config
   responses, and exclude login query strings from access logs (OAuth codes).
5. Enable the existing authorized live SSE routes in TEST. Preserve streaming
   responses and disable proxy buffering on those routes. This code does not
   grant or change server roles, module access, or object-level meeting access.
6. Extend the approved bot package generated by platform-backend's
   `teams-capture-worker/teams-app-manifest/package.mjs`:

```sh
node scripts/package-panel.mjs APPROVED_BOT_DIRECTORY NEW_PANEL_PACKAGE_DIRECTORY https://testai.acik.com 0.2.0
```

   The output directory must be new and its version higher than the input. The
   script preserves the existing bot/app identity, icons, permissions and approved
   domains; it adds meeting side-panel/chat/details contexts. Validate the output
   in the Teams Developer Portal, zip its three files at the ZIP root, and install
   under the institution's TEST app policy. No tenant action runs during build.
7. Add the app to the TEST Teams meeting, sign in, choose the canonical meeting
   and save. Other viewers sign in with their own platform accounts; the API
   decides who can read. Confirm the deployed `SOURCE_COMMIT` and bundle hashes.

## Acceptance and remaining integration

Automated tests cover real SSE framing, live UI updates, wrong-meeting rejection,
source preservation, same-origin tokens, cancellation, revoked access and hung
access checks. They do **not** prove a real Teams/Keycloak login or tenant setup.

This panel consumes an existing meeting stream. Native Teams audio ingestion,
time-aligned participant-name mapping and the user-authorized Outlook selection
bridge runtime to the worker scheduler remain separate acceptance work. The
picker uses `/api/v1/admin/meetings/{id}/teams-calendar` from backend #1195;
it must remain disabled until the backend's activation conditions are met. Configuration
selects which existing platform meeting to display; it does not join a call or
automatically prove a Teams chat-to-platform mapping. Speaker labels remain the
canonical stream's labels; identity is not inferred from a name spoken aloud.

Before acceptance, run a real two-person Teams meeting: both users' own login,
authorized/unauthorized meetings, live transcript/decisions/actions during speech,
meeting-specific selection, logout, revoked access, reconnect and panel removal.
Repeat in the desktop Teams client and browser, including a narrow panel and large
text. Confirm gaps after reconnect are not presented as complete saved content.
Calendar tests additionally cover ambiguous mutation outcomes, denied access,
stale/unmounted views, truncation, response scope and explicit user selection.
Synthetic browser QA at 320px and 200% text verified selection, scheduling and
cancellation without horizontal page overflow. This is not real Outlook/Teams
acceptance, and no institutional account or live calendar was changed.
